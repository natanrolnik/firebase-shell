# firebase-shell

Consumes Google's **precompiled, vendor-signed** Firebase xcframeworks (the
`Firebase.zip` manual distribution) as SwiftPM binary targets, exposed through a
single `FirebaseKit` product.

## Why

Building Firebase from source via `firebase-ios-sdk` made our Tuist setup emit
each GoogleUtilities sub-product as a standalone dynamic framework, which tripped
App Store **ITMS-91065** (missing vendor signature, which ships only in this
precompiled distribution). Static-linking the source products instead stripped
ObjC category methods (e.g. `+[NSData gul_dataByGzippingData:error:]`) and crashed
at runtime.

The precompiled xcframeworks are **static and signed by Google**, so linking them
sidesteps both problems: static libs link into the app binary (no embedded SDK
framework bundle to sign, so ITMS-91065 never fires), and `-ObjC` keeps the
categories alive.

## Layout

- `Package.swift` — one `.binaryTarget(url:checksum:)` per xcframework (between
  the `BINARY_TARGETS_BEGIN/END` markers, regenerated by the script) plus the
  `FirebaseKit` target that wraps them.
- `Sources/FirebaseKit/FirebaseKit.swift` — `@_exported import`s the modules the
  app consumes (`FirebaseCore`, `FirebaseAnalytics`, `FirebaseCrashlytics`,
  `FirebaseMessaging`).
- `Scripts/make-release.sh` — downloads `Firebase.zip`, splits it into one zip
  per xcframework (`ditto`, preserving symlinks), computes SwiftPM checksums,
  regenerates `Package.swift`, and optionally uploads the assets via `gh`.
- `.github/workflows/release.yml` — runs the script for a chosen version.

## Frameworks included

Union required by `FirebaseAnalytics` + `FirebaseCrashlytics` +
`FirebaseMessaging` + `FirebaseCore` (17): FirebaseAnalytics, FirebaseCore,
FirebaseCoreInternal, FirebaseCoreExtension, FirebaseInstallations,
FirebaseCrashlytics, FirebaseSessions, FirebaseMessaging,
FirebaseRemoteConfigInterop, GoogleAppMeasurement,
GoogleAppMeasurementIdentitySupport, GoogleAdsOnDeviceConversion (iOS only),
GoogleDataTransport, GoogleUtilities, nanopb, FBLPromises, Promises.

> `GoogleAppMeasurementIdentitySupport` is included to keep AdId/IDFA attribution
> matching the previous source build. `GoogleAdsOnDeviceConversion` ships no
> macOS slice and must be disabled on Mac Catalyst, so it is linked only on iOS.

## Bumping the Firebase version

```sh
# Locally (downloads, splits, checksums, regenerates Package.swift, uploads):
gh auth login
Scripts/make-release.sh 12.14.0 --upload

# Or against an already-downloaded distribution, without uploading:
Scripts/make-release.sh 12.14.0 --source ~/Downloads/Firebase
```

Then tag/commit the regenerated `Package.swift`.

## Consuming from Tuist

Replace the `firebase-ios-sdk` package with this one and depend on `FirebaseKit`.
The consumer must apply the linker flags Google's README requires (`-ObjC`,
`-lc++`) plus `-all_load` so the dynamic `FirebaseKit` framework retains and
re-exports every Firebase symbol. They live on the consumer side (not here)
because SwiftPM `.unsafeFlags` would forbid using this package as a versioned
dependency. In `Tuist/Package.swift`:

```swift
.package(url: "https://github.com/natanrolnik/firebase-shell.git", from: "12.14.0")

// PackageSettings.targetSettings:
"FirebaseKit": .settings(base: [
    "OTHER_LDFLAGS": "$(inherited) -ObjC -lc++ -all_load"
])
```

Call sites then `import FirebaseKit` instead of the individual Firebase modules.
